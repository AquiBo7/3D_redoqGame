# 验收与部署标准流程

每次完成里程碑或部署更新时，严格按以下固定顺序执行，不得跳步、不得调换顺序。任一环节失败即停止，修复后从该环节重新开始。

## 1. 单元测试

```bash
npm run test
```

- 必须全部通过（0 failed）。
- 有失败时先修复根因，不得用跳过测试、放宽断言的方式"通过"。
- 若本次改动没有对应测试且逻辑可测，补充最小必要测试。

## 2. 构建与体积检查

```bash
npm run build
```

- `build` 脚本已包含 `tsc --noEmit && vite build`，必须零类型错误、打包成功。
- 检查 `dist/` 产物：
  - 首屏资源总量 **≤ 3MB**；其余资源按场景懒加载，不得把全部场景塞进首屏 chunk。
  - 确认 `vite.config.ts` 的 `base: './'` 生效，`dist/index.html` 中资源引用为相对路径 `./assets/...`，保证部署到 Qoder Sites 任意子路径可加载。
  - 确认无遗漏的 GLB / 贴图 / 音频静态资源（对比 `public/` 与引用路径）。
- 记录本构建的产物体积，与上次对比，异常增长要说明原因。

## 3. 实机验证（涉及界面或 3D 交互时必做）

- 启动 dev server（`npm run dev`），用浏览器工具实际打开页面操作，而不是只看构建结果。
- 必须覆盖：
  - 黄金路径：开始页 → 进入场景 → 交互/对话 → 状态推进。
  - 关键边界：横屏与竖屏切换、窄屏手机尺寸、底部 48px 安全区不被遮挡、手机端 pixelRatio 上限 1.5。
  - 本次改动直接影响的功能，以及相邻功能的回归。
- 控制台必须**零报错、零警告**（含 three.js 弃用警告、资源 404、CORS、WebGL 警告）。
- 验证结束后**关闭 dev server**，不要遗留后台进程。
- 若本机无法实机验证（无浏览器等），必须明确说明"未实机验证"，不得宣称成功。

## 4. 部署

- 部署到 Qoder Sites 时，**只更新已有的公开站点**（项目根目录的 `.一条截图.qoder.site` 描述符对应的站点），**不得新建第二个站点**。
- 优先使用 sites-hosting 流程对该已有站点发布，发布前确认构建产物为最新。
- 发布后打开线上地址复查：首屏可加载、资源路径无 404、控制台无报错。
- 汇报时给出：站点地址、本次构建体积、测试结果、实机验证结论。

## 完成标准

四项全部满足才算交付：单测全绿、构建通过且体积达标、实机零报错零警告、线上站点更新成功（如涉及部署）。
